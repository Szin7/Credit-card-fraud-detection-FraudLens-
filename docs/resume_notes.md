# Resume Notes

Based only on what's actually implemented and the metrics actually
generated by running this code (see `docs/model_card.md`) — nothing below
describes functionality that doesn't exist or results that weren't
measured.

## Resume Bullets

- Designed and built an end-to-end batch fraud-detection pipeline
  (ingestion with schema checks and audit manifests, rule-based row
  validation, leakage-safe feature engineering) orchestrated with two
  Airflow DAGs and persisted to a 5-table PostgreSQL schema, processing
  24K+ transactions per run with full per-run status/throughput tracking.
- Trained and compared 5 classification approaches (Logistic Regression,
  Random Forest, XGBoost, and two imbalance-handling strategies) for fraud
  detection under severe class imbalance (<1% positive rate); selected the
  champion by validation PR-AUC (0.96) rather than accuracy, measured
  SMOTE against class-weighting head-to-head instead of assuming a
  result, and reached 0.94 test PR-AUC / 87.5% recall at a threshold
  chosen via a documented precision-recall-cost tradeoff sweep.
- Built a 4-page Streamlit monitoring dashboard (risk overview, filterable
  transaction explorer, model performance with an interactive threshold
  analysis, pipeline health) on a custom design system reading exclusively
  from PostgreSQL, and containerized the full stack (Postgres, Airflow,
  dashboard) with Docker Compose for one-command local deployment.

## 60-Second Project Explanation

"FraudLens is an end-to-end batch fraud-detection pipeline I built to
practice both the ML and data-engineering sides of a real system, not just
train a model in a notebook. Transactions get ingested, validated against
explicit rules, and scored by a model pipeline that does feature
engineering and prediction as one fitted sklearn object, so training and
serving never drift apart. I trained and compared five approaches —
Logistic Regression, Random Forest, XGBoost, and two ways of handling the
severe class imbalance — and picked the winner by PR-AUC instead of
accuracy, since a model that never predicts fraud scores 99.5% accuracy on
this kind of data while catching nothing. Everything's orchestrated by two
Airflow DAGs — training is separate from daily inference on purpose —
persisted to Postgres, and surfaced in a Streamlit dashboard with an
overview, a transaction explorer, model performance metrics, and pipeline
health, all containerized with Docker Compose. It ships with a synthetic
sample dataset so it runs out of the box, but every metric I report is
labeled as coming from that sample, not the real Kaggle dataset it's
schema-compatible with."
